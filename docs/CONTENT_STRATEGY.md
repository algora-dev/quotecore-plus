# QuoteCore+ Content Strategy

> The definitive plan for blog content, SEO, and conversion. Every agent building content must read this document first.

## Business Goal

Drive revenue through two funnels:
1. **Contractor funnel:** free tools (traffic) -> blog (education/trust) -> free trial (activation) -> paid plan (revenue)
2. **Supplier funnel:** blog (authority) -> supplier landing page (value prop) -> phone call (partnership) -> monthly retainer + distribution

## Markets (priority order)
1. **UK** (primary - first content batch uses UK terminology, GBP, UK competitors)
2. **NZ** (secondary - existing NZ site,.co.nz domain)
3. **US** (tertiary - expand once UK content is proven)
4. **AU** (opportunistic - shared terminology with UK)

All content should use language that works across markets. Use "roofing" not "roofing and siding." Use GBP as default currency in examples but mention USD/NZD where relevant. Avoid market-specific slang.

## Messaging Pillars (inject into every post)

Every blog post must reinforce at least two of these four pillars naturally in the body copy:

1. **Faster** - speed wins jobs, first to quote wins
2. **Easier** - no learning curve, no spreadsheet headaches
3. **Cheaper** - free tools, free trial, paid plans from $19/mo
4. **More money** - quote faster = win more jobs = more revenue

## AI Keyword Strategy

AI keywords are growing fast and competition in construction is still low. But "AI" in a title can scare non-technical contractors. Rules:

1. **Dedicated AI posts (3 max):** AI in the title. Target AI-specific search terms. People searching "AI roof measuring" want AI - title matches intent.
2. **All other posts:** No AI in the title. Mention AI naturally in the body where relevant ("there's also a faster way - AI tools can do this from a photo"). Position as one option, not a requirement.
3. **No duplicate posts.** One post per intent. Don't create "AI version" and "non-AI version" of the same topic - that cannibalises.

## World-Class Article Framework

Every blog post must follow this structure. No exceptions.

### 1. SEO Meta
- Title tag: 50-60 chars, keyword near front
- Meta description: 150-160 chars, includes keyword + benefit + implicit CTA
- URL slug: keyword-based, hyphenated, no stop words
- Canonical: self-referencing
- BlogPosting schema + BreadcrumbList schema (handled by existing code)
- FAQPage schema where the post has an FAQ section

### 2. Article Structure
```
H1: [Keyword-rich title - matches title tag]
   Lead paragraph (50-80 words): answer the search query directly, 
   state the benefit, and mention "free" or "under 3 minutes" 
   where relevant. Let their guard down immediately.

H2: [Main section - the answer/body]
   - 800-1500 words depending on topic complexity
   - Real examples, real numbers, real scenarios
   - Shaun's first-hand experience where relevant
   - Tables, lists, step-by-step formats
   - Images/diagrams where they help
   - NO fluff, NO padding, NO AI-slop phrases

H2: [Worked example or practical scenario]
   - Show a real job example with real numbers
   - "Here's how a roofer in Manchester would price a 120 sqm re-roof..."

H2: Common mistakes / tips / things to know
   - Bulleted list of practical gotchas
   - This is the "experience" layer that AI slop can't replicate

H2: Free tools that help with this
   - Link to relevant free tools with brief description
   - "QuoteCore+ has a free [tool] that does this for you in seconds"

H2: FAQ (3-5 questions with FAQPage schema)
   - Real questions people ask (check People Also Ask in SERPs)
   - Concise answers (40-80 words each)

CTA block (existing component):
   - "Ready to quote faster?" -> /free-trial
   - Or "Try the free [tool]" -> /free-[tool]
```

### 3. Content Quality Standards
- **Word count:** 1200-2000 words minimum for pillar posts, 800-1200 for supporting posts
- **Originality:** Include Shaun's real experience, real job examples, real numbers. This is our differentiation.
- **No AI slop phrases:** No "in today's fast-paced world," no "revolutionize," no "game-changer," no "seamless," no em dashes in copy
- **Formatting:** Short paragraphs (2-4 sentences). Bold key terms. Use lists and tables. Break up text with H2/H3 headings every 200-300 words.
- **Evidence:** Every claim about the app or tools must match Product Truth above. No feature claims that aren't live.
- **Technical accuracy (CRITICAL):** If you are not 100% certain a technical claim is correct, do NOT include it. No guessing. No filler. No estimated numbers presented as facts. When unsure, either verify with Shaun, check the codebase, or omit the claim entirely. Wrong information with Shaun's name on it destroys trust.
- **Tone:** Direct, practical, experienced. Written by someone who has been on a roof, not someone who has read about roofing.

### 4. Conversion Elements
- **Early reassurance** (first 100 words): state it's free / fast / easy
- **Mid-content tool link:** one contextual link to a free tool in the body
- **End CTA:** the existing orange CTA block with trial or tool link
- **No hard sell in body:** educate first, sell at the end

## Publishing Workflow (HARD RULE)

1. Agent writes content as .tsx file in `app/(marketing)/blog/[slug]/content/`
2. Agent registers post in `app/lib/blog-posts.ts` (metadata) and `app/(marketing)/blog/page.tsx` (index)
3. Agent adds sitemap entry in `app/sitemap.ts`
4. Agent commits to a staging branch (NOT main)
5. **NOTHING goes live until:**
   - Shaun confirms in Telegram ("push [slug] live"), OR
   - The post is marked "ready" in the BLOG_BACKLOG.md and Shaun approves
6. When approved, agent merges to main and it deploys

## Content Backlog File

`docs/BLOG_BACKLOG.md` tracks every post through the pipeline:
- Status: planned -> drafting -> draft-complete -> in-review -> approved -> published
- Owner: which agent is writing it
- Keywords, links, CTA
- Last updated date

Any agent can check this file to see what needs writing, what's in review, and what's ready to publish.

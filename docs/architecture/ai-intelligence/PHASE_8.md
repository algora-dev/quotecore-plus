### Memory management

`app/lib/intelligence/learning/memory.ts` reuses `MemoryRecord`, `parseMemory`, `activeMemory`, Phase 1B `Transaction` and the policy/digest helpers. `MemoryStore` extends the server-side transaction projection with a journal, scope-specific inspect/manage permissions, source/promotion validation, and current approver authorization. The adapter must enforce these predicates against trusted server state under the company lock, not accept them from the browser or model. A proposal is explicitly scoped and source-backed; no automatic promotion or legacy proposal activation. Company-wide promotion of private knowledge requires explicit source-owner consent. No full conversation copying.

Human review binds the exact record, origin, actor, job input/version, memory journal revision and policy revision. Approval increments the record version, records actor/time, and requires explicit supersession IDs for competing active records of the same scope and subject. Rejection/revocation/reset are scoped and audited; they remain available with the feature disabled, subject to current human ACL. Reset is logical retirement, not deletion. Historical records and change journal need a restricted retention policy. No learning output directly changes a pricing rule, product library, scope exclusion, template, legal term or communication permission. The Phase 1A agent `admit` still refuses permanent activation; `decide` is a distinct explicit human-only command (not an agent tool). The integration must require authenticated UI action, protect against CSRF and enforce independent scope permissions; a review hash is not itself an approval credential.

Retrieval is exact requested kind/subject key matching, with normalized case/Unicode, only approved, unexpired, current-source and current-approver records. Conflicting contents across otherwise visible scopes are withheld, not silently overridden. Returns advisory records, not executable instructions. No embeddings or free-form model ranking. Source authorization must pin exact source versions, ensure access and consent at retrieval/activation, and invalidate revoked sources. `recordUse` binds a draft ID to a selection digest; `checkUse` re-evaluates and reports stale drafts when selected knowledge, job input/revision or policy changes. Callers must supply canonical relevant subject keys and bind them and the exact draft version to the existing approval/persistence pipeline; no client-supplied shortcuts, and failures/disabled state must fail closed. The current service is human-context only; autonomous retrieval must be explicitly authorized later, not impersonate a human. No existing Phase 5 approval path is modified yet. Actual cross-job draft notifications, cache invalidation, UI, export workflows, deletion/retention workflows and durable journal storage remain integration tasks. `inspect` returns a scoped structured projection, not a complete export of historical records/source documents. Any source identifiers and origin metadata require ACL review before UI exposure.

### Follow-ups

`learning/followups.ts` defines a read-only `FollowupStore` and versioned approved policy/template/quote communication projections. Only existing `quote_sent` no-response follow-ups are proposed initially. The existing `app/lib/send-document/followups.ts` dispatcher and `app/lib/messages/scheduled.ts` remain authoritative for schedule/send; they are inspected, not invoked or changed. Require an exact sent receipt and unchanged quote/recipient, awaiting-response status, affirmative consent, no cancellation/pending follow-up, active Intelligence and follow-up entitlement, current approved template/policy, minimum delay and gap, maximum count, and company-local quiet hours. Delay uses elapsed 24-hour days; quiet-hour windows are whole hours and respect IANA timezone (including overnight). Proposed caps (1–365 days, 1–10 follow-ups) are provisional limits, not activated defaults. No actual template rendering or interpolation. Preview includes the existing template text, exact digest and deterministic sequence key. Review rechecks all dependencies and returns no schedule/send authority. The existing scheduler must handle actual due-date semantics: do not pass elapsed delay blindly to scheduler (its quote_sent scheduling is relative to schedule time); verify canonical timing, idempotency, locking, cancellations, status/recipient/consent, provider receipts and quiet-hour handling again before scheduling and dispatch. Unknown events or consent block readiness. No live communications.

### Outcomes

`learning/outcomes.ts` aggregates trusted company quote outcome rows for a sent-date cohort (exclusive end) with explicit counts, acceptance among decided quotes (accepted + declined), median observed response time, missing feedback count and simple advisory suggestions. No inferred decline reasons, causal claims, raw customer comments in output, or pricing changes. A server adapter must authorize company-wide analytics, enforce privacy/retention and canonical event mapping, exclude demo rows, limit cohort sizes, and document sample completeness. No outcomes are fetched here. No claims of review-time, conversion or cost improvements have been measured. Repeated-correction automation, workflow recipes, new roofing packs and personalisation UI remain outstanding.

## Delivered

- `app/lib/intelligence/takeoff/vector.ts`: strict vector-endpoint proposal projection from a ready Phase 2B brief and Phase 3 explicit written dimension hints. Binds current evidence ID, fact/version, document revision, page hash, transform version and displayed rotated raster dimensions. Reuses `buildSourceToScene`, `applyAffine`, `distance`, `parseDistanceSuggestion` and `convertDistance`. Source raster endpoints must be explicitly associated with the dimension; never derive endpoints from OCR text bounding boxes. Enforces bounds and rejects degenerate vectors, stale evidence and unrecognized fields. Same-page candidate scale disagreement and human-associated cross-drawing dimension disagreement are flagged above a provisional 1% relative difference; the threshold is advisory only, not the existing calibration acceptance policy. No automatic scale selection, registration, calibration commit or geometry changes. Raster dimensions and endpoint association are supplied by the trusted future adapter/human review; not independently authenticated by this pure projection. No real PDF vector parser was added or exercised.
- `optimise.ts`: uses canonical offcut `deriveFaces` for topology suggestions, always resets confirmation and pitch to unknown. Existing face review, direction approval, partition and profile validation remain authoritative. For reviewed/calibrated faces, uses existing `frameFor` and `sceneToSurface` for independent per-plane surface geometry, area and local 3D coordinates (cross-slope x, downslope horizontal y, z up relative to face origin). No shared vertical datum, absolute elevations, intersection fitting, multi-page registration or watertight mesh. Existing grassfire 3D preview is approximate and not used as a measurement authority. A true explicit 0° pitch is supported; unknown is never substituted with 0°.
- `optimise.ts` also runs the unchanged canonical `optimise` solver (v2.30) outside any database transaction. Rechecks inputs and results using `quoteQuantityProposal`, which calls existing `validateDraft`, `rootSheetLedger` and `quantitySummary`. Retains purchased root sheet quantities, net roof area, effective-cover and configured-profile area bases, assumptions, and warning messages. No separate material algorithm, AI cut lengths, ordering, extra spares or labour quantity writes. Bounded search is not proven optimal. Pilot limits: 400 selected boundary segments, 32 faces/outlines, 600 face polygon/boundary elements, 32 trials, 4 seconds base search budget, 600 sheets; optional global-bank and provisional-reuse search must be explicitly off. These are provisional conservative limits, not hard wall-clock or memory isolation; host must provide separately bounded worker, cancellation and output caps. `compareProfileSupply` compares physical supply for two separately reviewed distinct profiles on identical geometry and settings. No commercial ranking, installed-product equivalence, supplier compliance or rate substitution. Both profiles must be authorized and independently checked by the host before any comparison. No automatic selection or writes.
- `service.ts`: unregistered read-only authenticated `TakeoffStore` port. Fresh scope/actor/policy/entitlement/review checks, current analyzed page and source/transform binding, current brief and completed/reviewable document task, no active work, quote/image/profile mapping, geometry and library revision hashes. Uses existing explicit `prepare_measurements` admission and additional takeoff review access; integration must separately authorize offcut feature access and worker compute. Server-only preparation provides exact request and actor-bound preview digest; review accepts only a quantity basis and a current result tagged with the original preview digest. Rechecks canonical inputs and physical results; never trusts browser/model result or arbitrary quantities. The digest is not a signature or authorization. No writes to any geometry, measurement, component, price, approvals or purchase order. Result origin/ownership and worker fence must be authenticated by adapter. Pure helpers consume trusted typed legacy DTOs, not raw AI/browser JSON. `legacyDigest` strips undefined optional fields from these DTOs; rejects nonfinite numbers; existing JSON digest caps apply. No public routes or UI mounted.

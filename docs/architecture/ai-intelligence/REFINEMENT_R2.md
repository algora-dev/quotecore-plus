# R2 — Intelligence Hub and low-touch decisions

Status: additive, isolated hub service and unmounted React component. Based on e2209d3e + 1A–8 + R1; not Gavin's integrated branch. No deployment, migrations, dependency changes or changes to previous code. Continue isolated Vercel and Supabase branch strategy. Feature default off; manual app remains unchanged.

## Product contract

One account, one canonical quote/job identity. Job Spaces stays exactly as it is for manual use. Intelligence is a sibling optional hub/landing preference, not a duplicate estimating engine or job database. Draft quote IDs are canonical before Job Spaces lists them; use existing finalisation when the estimate becomes a job space. Never copy estimates into a second job. New intake assignment should use existing canonical create/associate operation. Account defaults, job/task override, user-selected landing view and actual navigation wiring are still needed. R1 remains the coordinator, existing measurement/takeoff/pricing/quote systems are authoritative. Do not relax approval or feature flags just to reduce clicks.

The hub should answer: what is being worked on, what is queued, which decisions need me, what is assigned to me, what is ready to review. No fabricated percentage or claims that queued work is actually running. Decisions display source, recommendation, option effect and explicit actions. Human takeover from a real saved checkpoint must be atomic with worker fencing; after editing, delegate again and resume affected work. Natural-language requests (voice or text) prepare a proposal, not an unrestricted write. Keep a clear link to manual tools at all times. Actual final send approval remains separate.

## Delivered files

- `app/lib/intelligence/hub/model.ts`: minimal browser-safe task/job view, state labels and counts; typed allowlist for UI commands, instruction request and preview-only response. No lease tokens or raw action payloads in view.
- `app/lib/intelligence/hub/service.ts`: authorized company/quote projection via adapter; checks actor identity, entitlement, policy, version and quote scope. Adapter must independently enforce membership/quote ACL and return only authorized job IDs. Source metadata comes from current evidence adapter. Recursively checks ancestor artifacts, marks stale outputs/interrupted workers, withholds decisions with stale dependencies and options with missing evidence. Counts actual running leases rather than queued work. Final `prepared` is only a current draft, never send readiness. Validates exact decision version/digest, rechecks evidence/option and ancestor validity, invokes R1 selection (records proposal only), assignment, pause, resume, and combined `takeover_resume` within transaction. Combined command fences worker and validates checkpoint before committing ownership; actual hydration happens subsequently via existing editor. Return resume locator to server host, not public endpoint; never expose storage URLs or raw checkpoint metadata in browser. `validateInstruction` binds quote/revision/task version and editable transcript to authenticated human; it neither invokes model nor applies action. Adapter must enforce atomic locks/rollback/audit, trusted time, fresh canonical checks, and server-only command handling. Scope list max 500 is provisional; implement cursor pagination and batch authorized reads before scale.
- `app/components/intelligence/IntelligenceHub.tsx`: unmounted responsive v2-primitives component with job filters, task details, evidence-opening callback, prepared option selection, assignment, pause, single-click takeover/resume callback, manual navigation, refresh and text instruction proposal surface. Existing Smart Assistant `useVoiceNote` reused only when host enables voice. Never arms auto-send; displays editable transcript and explicit proposal submission. Host owns callback authorization, navigation, current view, permission/entitlement and error handling. No live speech, model, storage or UI route provided. Proposal summary cannot execute changes; host must translate into actual server-owned prepared decision with a fresh preview. No silent auto-refresh or optimistic commit claims; use server action + current snapshot, then eventual push updates when integrated. Real source highlight is resolved from evidence ID on server, not fabricated client coordinates. No signed URLs in DTO. Clarification selection is not communication.
- `tests/intelligence/r2.test.ts`: 16 focused cases for view privacy, readiness, stale evidence/option/ancestor, version replay, pause, exact checkpoint, combined takeover rollback, cross-company and actor mismatch, disabled/revoked access, read-only actor, text/voice proposal validation and disallowed commands.

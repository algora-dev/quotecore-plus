# R1 — Shared-job coordination and delegation foundation

Status: isolated, additive, partial implementation. Baseline e2209d3e + phases 1A–8. Gavin's integrated branch is not available. Do not deploy or replace it. All new functionality remains unmounted/default-off. This document supplements PRODUCT_REFINEMENT.md; it is not a production acceptance report.

## Product decisions

One job, two views. `app/(auth)/[workspaceSlug]/job-spaces/page.tsx` delegates to `QuoteIndexPage`, and `job-space-list-model.ts` explicitly filters draft records. Use the existing canonical `quotes` ID throughout. Intelligence intake can remain unlinked pending customer/project identity; create or associate a canonical draft once authorised, then use that same ID until the existing finalisation operation makes it visible in Job Spaces. Do not create a duplicate job-space table or copy a completed estimate into a second quote. Existing manual workflow, job-space list, status transitions and sending remain authoritative.

Add an optional sibling Intelligence hub/tab, configurable landing page, and a single task inbox. The hub shows assigned work, ready/working/needs-input/waiting-external/ready-for-approval states, current canonical totals, and explicit unknowns. Account defaults seed new task assignments; job and task overrides take precedence. A change to ownership must fence an active worker before editing. Don't require assigning irrelevant tools (a stated quantity route doesn't need a duplicate digital takeoff). Pausing Intelligence must not stop normal manual application operations. Use existing v2 primitives and design system when implementing the UI. Preserve Job Spaces navigation. No new UI is mounted by this package.

## Implementation

- `coordination/workflow.ts`: fixed, bounded per-area dependency graph with a shared document/requirements stage, independently runnable scope allowances, quantity route, profile, optimisation and pricing nodes, then quote draft. The quantity route selects exactly one source path per area (stated or digital). This is a provisional area-level pilot; mixed source types for separate components within one roof area, non-roof trades, optional/nonapplicable optimisation and richer cross-area dependencies need a future validated graph. The fixed graph doesn't execute models or calculations; all artifacts require authoritative validation. It defaults to human task ownership, does not bypass the 1A action allowlist, and has no send tool. An unresolved route/profile blocks its dependants, not independent roof areas. Final quote-draft readiness waits for all declared predecessors; provisional partial prices can be displayed, not released as a final quote. No fake progress percentages.
- Task assignment, pause, lease/fence token, expiry/recovery, dependency invalidation, and saved checkpoint references support takeover and resumption. Each node has an expected version. A manual canonical save or new revision invalidates affected work, not independent branches. Checkpoints refer to existing saved editor state, scoped by company and quote, with record/version/hash and optional page/selection IDs. They do not contain actual geometry. Handoff returns a typed locator, not an invented URL. The adapter must prove the checkpoint exists/current and that the real editor can hydrate the exact state. Invalidation clears stale checkpoint references; underlying canonical audit history must be retained by the adapter.
- Prepared decisions have source evidence IDs, a question, alternatives, effects, target/version and payload hash. Exact preview binds actor/scope/policy/job revision/dependency versions. Selection only records the chosen proposal; it is not an engine commit or approval receipt. Revalidate the target, actual payload and actor authorization in the canonical transaction before applying. A request for clarification must stage a draft and stay blocked until answered; no communication is sent by R1. For a custom text/voice instruction, transcribe with user consent, resolve to the same typed proposal, surface ambiguity or preview, and run identical validation. No unrestricted natural-language writes. Actual speech and UI are not implemented.
- `coordination/libraries.ts`: uses the existing Smart Assistant `normalizeAssistantCallName` and `LibraryCatalogItem` contracts; exact library name/call-name matches from an adapter-provided authorized active catalog, with settings epoch. Collisions are withheld. A match is a suggestion, not confirmed profile compatibility or approval to price. Reuse Smart Assistant library setup and product/concept/default rules (`account/smart-assistant/AssistantLibrarySettings.tsx`, `library-actions.ts`, `workflow-controller/configuration.server.ts`, `decisions.ts`); do not maintain duplicate library names. Verified company policy may eventually permit specific unambiguous profile defaults; explicit uncertainty remains a prepared decision.
- `coordination/service.ts`: transaction port for authoritative scope, actor, artifact, checkpoint and option checks. No live store or runtime registry dispatches tools. Server must implement atomic compare-and-swap/locks, trusted time and audit, access check, bounded retries, provider spend reservations, scoped staging and existing approval requirements. Never treat a hash as authorization. Prevent any direct client access to graph mutation or artifact completion; commands originate from server adapters. Lease and preview bind global job revision conservatively; simultaneous independent writes may require refresh/retry. Earlier phase services reject some edits during active tasks and require user approval; these remain unchanged. Before enabling parallel execution, agree scoped revision/lock model, risk-specific approvals and transactional invalidation with Gavin. The prototype's queue is a projection, not proof a scheduler is running. No provider call, live worker or app write occurs in R1 tests.

## Real integration sequence

1. Establish authorised intake-to-canonical-draft association with existing create/quote action. Attach docs and source revisions. Keep existing 50 MiB per-file cap and budget/permission gates. Reconcile latest integrated branch.
2. Connect Phase 2A/2B document/brief results, with bounded coverage and typed decision proposals. For each scope/area, choose stated verified quantities (units, plan/surface basis, pitch, completeness, duplicate risk) or digital measurement, not both for the same quantity. Use existing geometry and import validation; unresolved overlapping sources require review. Never use an AI guess for dimensions.
3. For digital takeoff, persist staged real plan pages, calibration, contours/segments, classified features and viewport or selection state through the existing workstation persistence. Existing route is `/{workspaceSlug}/quotes/{quoteId}/takeoff`; it already loads a company-scoped quote, plan file and hydration. Checkpoint locator must use existing state and editor page-selection implementation; exact state hydration is not yet proven. Protect active human editing, preserve undo and provenance; resume on the same quote ID, not a new drawing. Existing measurements route for stated quantities and builder route for pricing. Do not fabricate deep-link query keys.
4. Resolve approved product libraries via existing call names and exact settings version. Verify physical compatibility, approved rates, quantities and scope through existing pricing and optimisation engines. Record provisional outputs even while unrelated decisions are outstanding. No premature estimate approval.
5. Finalise canonical quote with existing approved operation, then expose it in Job Spaces. Prepare customer quote and send only through existing exact-version approval and sending system. Track customer outcomes; follow-ups follow existing policy. Do not send from the coordinator.
6. R2 UI: Intelligence hub beside Job Spaces, settings/landing choice, task delegation and handover, decision drawer (source highlight, proposed answer, commercial delta from real engine, confirm/edit/instruct, open exact editor), text/voice command surface, notification controls. One click when safe; no mandatory chat. Manual and automatic changes converge through the same records. Voice must display transcript/action preview and use identical authorisation; no always-listening by default.
7. Continue R3 commercial lifecycle and R4 actual job costs: supplier invoices, credits, labour/time, variations, allocation, estimated vs actual direct costs, margin and learning proposals as previously specified. These are not implemented by R1.

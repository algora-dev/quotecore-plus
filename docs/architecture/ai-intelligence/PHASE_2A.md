# Phase 2A — bounded document worker (local vertical-slice foundation)

Baseline e2209d3e + delivered 1A/partial 1B. No application wiring or deployment. This milestone implements the worker and an offline PDF parser/raster proof. It does **not** certify a production parser, a live provider or a distributed worker. Phase 1B database integration gates remain mandatory.

## Delivered

- `documents/pages.ts`: verified-source metadata -> bounded immutable page manifest, SHA-256 original-byte verification + first signature filter, normalized text-region boundary, server-created evidence, strict page-local typed candidate validation. The existing 50 MiB per-file cap is unchanged. Pilot fixture defaults: 20 files, 150 MiB packet, 200 pages, 80 text regions and 24,000 UTF-8 text bytes per page; 2,000 output tokens, 15-second local await limit. Defaults require owner/runtime approval before production. Page hash is a digest of immutable original content hash, page index and transform version; it is not a raster-byte hash. Storage and parser must independently prove actual source identity and transform correctness.
- `documents/worker.ts`: one page per invocation; worker lease, fence, job scope, input hash, policy, fresh authority and feature flag verified at selection, request-intent commit and result commit. Atomic route/reserve + intent, separate external call, atomic settlement + evidence/output checkpoint. No network inside transactions. Model routing reuses the Phase 1A trusted registry; no production model or rates assumed. Duplicate same-version dispatch is fenced; completed pages are skipped on restart. Crash after dispatch intent cannot prove whether the provider ran, so keep funds held, mark the page failed and wait for reconciliation. Late results cannot write stale output. Known usage is settled even when generated candidates fail validation; unknown usage or actual overage stops work. No auto-retry for an ambiguous charge. Cancel/revoke/expiry may leave an intent and held funds requiring a separate reconciliation service. In-flight network operations cannot be retroactively undone by revocation. No issue/fact is confirmed and no measurement or pricing change occurs.
- `documents/provider-adapter.ts`: optional, default-off transport wrapper with explicit registry-to-provider-model mapping, request/output bounds and abort signal. No actual SDK/network implementation or credential wiring. Transport must enforce hard timeouts, response size before buffering, no tool access or hidden retries and authoritative settlement. The worker's await timeout cannot kill a transport that ignores abort. The worker only routes to reviewed enabled models; deployment must exclude unavailable transports from the registry. Conservative UTF-8 input bound plus 2,048 framing tokens requires real provider tokenizer/framing proof. Do not automatically send customer data to a provider without approved retention, privacy and provider configuration.
- `persistence/store.ts`: adds optional `documentRun` to existing Phase 1B state. This is the only prior intelligence file changed, with type-only import. Transaction adapter must serialize/persist the manifest, page intent, output and settlement atomically. No migration changes.
- `tests/intelligence/phase2a.test.ts` + fixture: actual generated 30-page PDF and extracted regions from an offline PyMuPDF/ReportLab experiment. The Node worker tests consume the extracted fixture through a simulated reader/provider/store. Each PDF page was extracted and rasterized locally at 306x396; a separate synthetic rotated vector page rasterized at 396x306. These prove local tools on synthetic examples, not production renderer availability, arbitrary PDF safety, OCR, rendering parity, model quality or performance. Optional generation script uses local Python packages; no npm dependency changes. PyMuPDF licensing and runtime suitability require explicit review before adoption; the experiment is not a proposed production dependency.

## Worker usage and limitations

Trusted server handler verifies finalized uploads (immutable private storage ownership, actual bytes, hashes, signatures, parser metadata), creates/claims the existing analyze task, calls `initialize(scope, workerActor, token, verifiedDocs)` and persists resulting state. Scheduler calls `runOne` with the returned live task token; each invocation processes at most one page or terminal/recovery action. Reload state after process failure; use 1B recovery and claim on expired leases. Do not expose these methods to browser callers. Actor/grant/trigger provenance remains a 1B integration requirement. The pilot assumes one initial active packet/run per job; archive/revision/reanalysis workflow is deliberately blocked pending durable immutable history. No inactive document auto-selection. Image signatures are recognized by the byte verifier but no raster input decoder is shipped. Pasted notes and OCR/vision are outstanding. `PageReader.textOnly` is a trusted parser determination, not a model verdict; blank, drawing-heavy, rotated/unproven or non-text-only pages must be screened/failed rather than silently counted as analyzed. Model relevance is only a candidate; it does not change source ownership or remove pages. Coverage derives from manifest, not model. Text candidates have exact source regions, but textual entailment and correctness still require human review.

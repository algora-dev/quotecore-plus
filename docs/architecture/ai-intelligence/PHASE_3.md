# Phase 3 — measurement and Scan Assist preparation (isolated)

Baseline e2209d3e; additive to phases 1A / partial 1B / isolated 2A / isolated 2B. This is the read-only handoff preparation layer, not a mounted or live measurement integration. The implementation-plan milestone is **not complete** until the existing review/import and Scan Assist paths are connected and validated in testing. No changes to protected files, legacy routes, billing, migrations, upload limits, dependencies or original app behavior. Intelligence stays default-off. No production or external AI calls.

## Delivered

- `app/lib/intelligence/measurements/prepare.ts`: accepts trusted parsed brief, uses existing brief readiness and review-version checks, holds non-explicit, non-positive, non-scalar, unrecognized/mismatched unit, missing literal, overly long label, shared evidence and identical quantity records. Never aggregates, estimates, guesses units or converts values. Anchored scalar reader intentionally narrow: compound N x M, ranges, mixed/fractional and locale formats go to manual review. Retains source values, original units, basis, fact versions, current evidence, source text, page/transform identity. Display units mapped to existing import aliases. `surface` maps to `actual`, `plan` to `plan`, count stays count in metadata and is projected as `actual` to avoid plan pitch; component family/settings must still be verified. Pitch facts remain separate context; no assignment to a roof/component or use in calculations. Every projected line has status `candidate`, no component match, no guessed unit, no combine, no selection. No UI ready-to-price claim.
- `prepare.ts` suggests selected/relevant pages (not proven roof plans) with content identity and transform version, and explicitly titled dimension/calibration references with a consistent written length and current source evidence. Reuses baseline `calibrationCandidates.parseDistanceSuggestion`; hints never create endpoints, calibration candidates with geometry, scale, scene transforms or editable outlines. Evidence boxes are normalized text/source regions only, not scan geometry. A human must verify actual plan and calibration endpoints with the existing workflow.
- `app/lib/intelligence/measurements/service.ts`: read-only authenticated quote-only preview/recheck/handoff through `IntelligenceStore`. Explicit `prepare_measurements` capability; fresh entitlement, actor, scope, review permission, policy and job revision; same persisted document manifest, terminal/reviewable document task, no active work/in-flight document call. Reconstructs from server brief, not client-supplied facts/lines. Digest binds scope, actor, policy version, input hash and exact preview, not an approval token/signature. Handoff selects unique eligible fact IDs (max 60, legacy cap), and optional single currently analyzed page. Returns selected rows and page-specific calibration hints, no writes, no worker start. Recheck denies incomplete review. A digest check is a point-in-time preview, not a transaction authorizing subsequent effects. `ready` means brief review readiness, not import, calibration, pricing or send readiness. Manual path remains available independently of Intelligence.
- `tests/intelligence/phase3.test.ts`: 13 isolated tests exercising reviewed document-run -> real Phase 2B review service -> phase 3 preview/handoff, source/basis/pitch, unit aliases, stale evidence, blocked review, duplicate and compound readings, source literal boundary, forged inputs, scope/authorization, task state, stale digest, selected pages and calibration hint limits. Existing 96 tests rerun. Strict isolated TypeScript compile succeeds; 109 intelligence tests pass. Existing `calibrationCandidates.test.ts` and `calibrationCoordinates.test.ts` also compile and pass (22 tests, not full calibration suite).

## Deliberate limitations / decisions requiring validation

Whole-brief readiness is conservative; incomplete coverage or open issues block candidate selection even if one quantity is already reviewed. Hold ambiguous, derived, inferred, shared and same-value/unit/basis readings (may over-block legitimate equal dimensions in different zones); other duplicates, alternate units and semantic scope mismatches require manual review. Literal matching is narrow, not semantic proof. No global pitch or geometry inference. Calibration hints require a reviewed explicit quantity titled dimension/calibration/scale reference with plan basis and written matching unit; many true references will be missed. Page suggestions are relevance/selection-based, not plan classification. Large previews may exceed existing 1 MB digest contract, fail closed and need paginated admission design. No real database, Zod import runtime, worker, UI, scan/calibration commit or production validation. No original code modifications. Phase 4 may be designed in isolation against reviewed measurement snapshots, but live estimate/pricing reconciliation requires authoritative imported measurements and existing saved library/rate/rule engine; do not price from raw candidates. Recommend Gavin integration of 1A–3 now before enabling any actual writes.

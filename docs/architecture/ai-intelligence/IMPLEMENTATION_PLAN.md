# QuoteCore+ Intelligent Workspace — implementation plan

**Version:** 0.2.1 · **Date:** 2026-11-26 · **Baseline:** `e2209d3e6137748d66c589e6cdc8ad0aac487d76` (archive timestamp 2026-11-24).  
**Companion:** `ARCHITECTURE.md`.  
**Status:** Static discovery and proposed engineering sequence. Not a deployed feature, migration, or claim of tested runtime behavior. The supplied brief describes the snapshot as development/main/production parity; this was not independently verified against Git or the live deployment.

## 1. Executive decisions

1. **Do not build a second app or jobs table.** A Job Space is an index of existing quote records. A persistent agent, source records, analysis revisions, tasks and issues extend the existing `company_id` / `quote_id` identity. A pre-quote intake can have an intake ID until an existing draft-creation service creates the canonical quote. Do not bypass quote quotas by creating speculative drafts.
2. **Reuse, don't replace, Smart Assistant.** Its configuration, knowledge retrieval, action proposals, permission checks, working brief and task/session infrastructure are valuable. A separate bounded job runner is needed because a conversational turn is not a durable unattended multi-document workflow. Bridge the two through validated domain tools; do not fabricate a chat session or impersonate a user.
3. **First delivery is a real document-to-review vertical slice**, not a universal agent rewrite. Company-scoped settings, typed records, a persistent job brief with exact source references, a page-level worker and a measurement handoff. Manual workflow must remain intact. Extend downstream stages after evidence.
4. **Database is authority; Markdown is projection.** Structured facts, source versions, decisions, product records and policies are queryable and versioned. Markdown is a deterministic, compact representation for model context, human inspection and export. Do not execute Markdown, store arbitrary agent scripts, or permit model edits to security policy.
5. **No infrastructure or billing bypass.** Additive migrations, runtime configuration, worker scheduling, storage limits and entitlement changes require authorized integration review. Existing manual users must not be forced to pay for or use intelligence.

## 3. Proposed architecture: modular monolith plus bounded worker

Keep Next.js, React, TypeScript, Supabase and existing tool boundaries. Use new domain code under `app/lib/intelligence/` (proposed, not existing). Separate pure domain functions from authenticated entrypoints and worker-only execution. A provider adapter consumes normalized page evidence and returns schema-validated candidates; it cannot write directly. A worker only receives opaque task IDs, not untrusted tenant IDs or commands. Its service identity reloads the row, checks a company grant, job linkage, current mode, policy/permission revision, entitlements, budget and current input version before each operation. No request-cookie assumption in unattended tasks. Owner/admin authorizes an explicit scoped automation grant; revoke or suspend it and no new work may start.

Possible modules:

```
app/lib/intelligence/
  contracts/          # typed zod schemas, state and version contracts
  policy/             # mode, grants, approvals, budgets, risk gates
  knowledge/          # roofing packs, product facts, retrieval, learning proposals
  documents/          # manifest, page normalization, evidence mapping
  brief/              # candidates, conflicts, prioritization, markdown projection
  orchestration/      # durable tasks, dependencies, leases, checkpoints
  models/             # capability registry, provider adapters, usage attribution
  adapters/           # existing quote/measurements/scan/pricing/quote/message services
  review/             # read models, issue decisions, approval invalidation
  presentation/       # allowlisted workspace config, later
```

These are boundaries, not a requirement to build all modules at once. No new npm dependency in first pure-contract change. Need prove server PDF raster/OCR implementation in a worker; PDF.js and sharp are present but do not together guarantee a working rasterizer for every PDF. If additional native tooling, queue provider or container worker is required, present dependency/licence, cost, resource limits and security proposal separately. Do not run models in request handlers for a 30-page packet.

## 4. Persistent schema design (logical proposal, not migration)

Map all tenant IDs to **company_id**, canonical job identity to **quote_id**. All IDs are opaque UUIDs; foreign keys or transactional validation must enforce same company, not just globally unique IDs. Exact existing SQL, RLS, grants and migration root must be confirmed by Gavin. `assistant_configs` and existing knowledge tables should be extended only if safe; new proposed tables are namespaced `intelligence_*`. Never store a duplicate price library, customer quote, geometry graph or send ledger.

| Record group | Key fields / invariants |
|---|---|
| `intelligence_profiles` / grants | company ID unique, enabled modes per capability, revision, authorized actor/grant, allowed tools, retention settings, model/budget policy. User preferences scoped to user and company. New profiles disabled. |
| `intelligence_intakes` | company, optional quote ID, creator/grant, source type, request metadata, dedupe key, status. Manual first; inbound message ID later. |
| `intelligence_sources` / pages | company, intake/quote, object key, byte count/hash, MIME, source revision, original file reference; page index unique within source revision, drawing number/revision, rotation/crop boxes, text/render hashes, processing status, coverage. Keep original immutable until permitted deletion. |
| `intelligence_evidence` | company, page revision, normalized region or text spans, exact excerpt, extraction version, transform version; derived crops are reproducible. Evidence resolves through authorized signed access only. |
| `intelligence_facts` / issues | company, quote or pending intake, typed kind and value/unit, provenance class, evidence IDs, severity, status, source revision and supersession. Issues reference canonical estimate lines/components and explicit resolution decisions. |
| `intelligence_brief_revisions` | company, quote/intake, immutable input manifest digest, facts/issues, page coverage, knowledge/prompt/model versions, generated Markdown artifact reference. New revision never silently replaces human-approved values. |
| `intelligence_tasks` / events | company, quote/intake, stage, input digest, idempotency key, state, lease expiration, lease epoch/fence, attempts, next eligible time, checkpoint, error category, budget link. Unique stage/input/policy key. Transactional event/outbox for enqueuing downstream work. |
| `intelligence_approvals` | company, actor, immutable action digest, expected canonical record versions, permission/policy revision, expiry, single-use execution state; reuse existing action infrastructure where compatible. |
| `intelligence_product_facts` / learning proposals | private company scope, product/SKU/version, attribute/value/unit, source refs, region/applicability, approval and supersession. Never allow an uploaded PDF to become instructions automatically. |
| Usage | Extend approved billing reservation/settlement mechanism to include job/run/model and cost attribution. Record actual provider units and price version; maintain internal cost reporting without conflicting customer debits. |

Private conversation content remains owner-only per existing policy. Shared agent memory is created by explicit promotion of a reviewed fact or preference, not copying conversations wholesale. Global packs contain curated and licensed information; customer-specific data is never used for global learning by default.

### Execution invariants

- Distinguish business quote status from task state: queued, leased, processing, waiting_for_review, waiting_for_input, paused, succeeded, failed, superseded, cancelled. Derive readiness from coverage and unresolved blocking issues; a succeeded task is not a verified quote.
- Every task claim increments a fence. Commit requires matching fence, input digest and current policy/grant. Stale worker cannot overwrite newer output. Heartbeats renew only current claim. Recovery sweeps expired leases, cap attempts, preserve last valid checkpoint.
- Provider call identity and usage reservation are unique per actual attempt; ambiguous external result is reconciled, not blindly repeated. Calls are bounded and abortable. Pause/disable stops new claims and cancels cooperative work; already transmitted requests may still incur costs. Recheck permission and cancellation before persisting or side effects.
- Approval digest binds source, geometry, pricing and template revisions, totals, explicit exclusions, recipient and output snapshot as applicable. A changed dependency invalidates approval; never allow sending a changed quote under an old approval.
- Read policies for users must respect company plus section/job permissions. Writes via validated server actions/RPC. Service role never accepted from client. Test cross-tenant references, storage keys, revoked grants, user removal, billing status and public link isolation.

## 5. MVP document ingestion and brief pipeline

**First supported input:** PDFs and common raster images, plus pasted text/request notes. Batch upload of loose files; folder picker may simply select files. Defer archive expansion, email and native CAD until secure intake is proven. Retain the existing 50 MiB per-file cap. Packet and page limits configurable and separately approved; test a representative 30-page file at or below the cap, and safe rejection of oversized/adversarial files. Actual Supabase bucket/plan limits unknown. Use direct resumable upload if required; validate against signed quota reservations, actual metadata and content magic, not client claimed bytes. Avoid raising global signed upload cap. Do not send whole original to a model; use worker-created text and page images/crops under provider request limits.

1. Register manifest and immutable original object. Hash within company, prevent duplicate processing; never cross-tenant dedupe visibility. Keep originals private. Quarantine corrupt, encrypted, unsupported and suspicious content; bounded parser CPU, page counts, raster pixel/byte limits. No PDF JavaScript, embedded-file execution or network fetching.
2. Read each page using PDF text/operator extraction; preserve page index, rotation, dimensions and transforms. Render overview for visual screening. A blank text layer does not imply irrelevant page. Mark every page pending/processed/failed/unsupported with reason.
3. Low-cost page classifier identifies candidate roof plans, elevations, sections, details, general notes, schedules, specifications and revision blocks. Use selected roofing knowledge packs. Unknown/referenced pages are escalated rather than discarded. Every page gets coverage; no claim of full analysis if any page fails.
4. Extract typed facts and issues with page/region/excerpt references; use targeted high-resolution crops for dimension text and fine print. Preserve written values, units, pitch basis, product identifiers, scale candidates, scope qualifiers and confidence basis. Avoid final claims from model confidence alone. For each referenced detail/page, resolve pointer or create unresolved reference.
5. Reconcile revision and conflict evidence across documents. Never assume newest-looking filename wins. Mark superseded only with evidence or user decision. Detect contradictory slope/material, incomplete details, duplicate quantities, multiple structures and inconsistent dimensions. Any unresolved high-impact condition blocks ready state.
6. Compile a versioned Roofing Job Brief: scope, roof systems and pitch, material specs, underlay/insulation, special flashings, gutters/drainage, penetrations, access/height, safety/logistics considerations, removal/disposal, warranty/installation requirements, inclusions/exclusions, stated quantities, relevant pages, unresolved decisions and next step. Keep categories conditional and support nonstandard requirements. Do not assert every job needs each product or service.
7. Show reviewable findings ranked by potential pricing/scope impact, source deep-link and highlight. User can select relevant pages, reject/correct facts, resolve issues and continue manual measurement. A working-page selection is a view, not destructive deletion of source documents. Markdown projection generated from verified structured records; unverified sections clearly marked. Never trust a PDF instruction to change agent policy or send a quote.
8. Handoff: existing stated quantities become candidate measurement import rows via existing `measurementLineSchema`, `matchExtraction` and unit/basis checks. Selected roof plan becomes a proposal for current PDF page picker / takeoff flow. Suggest calibration reference; commit only using existing calibration validation. Manual fallback remains available at all times. MVP does not claim unattended geometry writes or pricing completion.

### Proposed review surface

Add a guarded Intelligent Workspace route alongside existing dashboard, not a replacement. Draft jobs show stage, coverage, blocking findings, last update and next action. Within existing quote summary add a Job Intelligence entry when enabled; panel links to source viewer and current manual tools. Use `QcSurface`, `QcButton`, `QcDialog`, `QcActionNotice` and `QcJourney` where appropriate; read v2 standards before UI code. Existing quote IDs and sidebar permissions remain authoritative. Batch review can approve compatible low-risk facts only when each is visible; sending remains per-quote reviewed action. Accessibility and mobile source detail zoom are mandatory.

Centralize routing for **new** functionality first; migrate legacy call sites one at a time with regression tests. No production model default changes in the first PR. A task policy defines model capabilities (vision, structured output, tools), max input/output, retry budget, version, deadline and escalation eligibility. Benchmark at least representative hand-verified documents: simple plans, complex mixed roof systems, poor scans, obscure specifications, detail references, contradictory revisions, existing measurement reports, regional products. Split development and held-out evaluation sets by job, not page. Propose initial 30 packages with roofing expert annotations then expand; not a measured dataset currently. Include 30-page input within the 50 MiB per-file cap and failure injection. Primary metrics: recall of high-impact requirements, false facts, evidence pointer validity, coverage, unit/scale errors, human correction time, per-stage and total cost, tail latency and time to reviewed quote. Pilot release gates: no untraceable confirmed fact; no silent incomplete analysis; no unauthorized/cross-tenant writes; no high-impact unresolved issue marked ready; zero duplicate side effects in replay tests. Accuracy and financial thresholds must be approved after baseline measurement. The 20 jobs/hour ambition is aspirational, not a guarantee.

# Phase 1B — transaction service groundwork (partial milestone)

Baseline e2209d3e; Phase 1A applied unchanged. Architecture 0.2.1. No production wiring.

New `persistence/store.ts` defines a server-side transaction port and typed state. `persistence/service.ts` implements default-off admission, task enqueue/dedupe, lease fencing, recovery/cancellation, company/job budget reservation and reconciliation, trusted brief revision writes, memory proposals, upload reservation/finalization metadata and single-use approval consumption with internal draft outbox intent. `tests/intelligence/phase1b.test.ts` supplies a serial copy-on-write fixture only. This is not durable persistence. All service inputs must originate from trusted server handlers; actor kind, authority, review, storage verification, settlement and approval receipts must never be accepted from browser/model payloads. No routes import the service.

## Integration acceptance gates

- Gavin must approve migration root, live schema, generated types, RLS/grants, canonical quote/intake linkage, worker identity and permissions. Implement database transactions/RPCs with tenant authorization, company budget locking and CAS/fencing, unique keys, durable audit, trusted database time, rollback and concurrent tests. The transaction callback port may need mapping to explicit RPC commands; do not emulate transactions with multiple independent Supabase HTTP requests. Load only required records, not unbounded company history. Validate fresh authority and explicit request provenance, including worker delegation and revocation. Feature flag must default off in production.
- Confirm budget window, pricing versions, settlement authority, provider request idempotency and crash reconciliation. A reservation marked created is not a provider execution guarantee. Never release uncertain usage; no actual model calls included.
- Integrate existing signed uploads/private bucket and quota enforcement, verified actual file bytes/hash/signature, storage key ownership, page manifests, packet limits, expiry/orphan cleanup. Metadata methods alone do not authorize storage. The 60-second metadata reservation is a provisional fixture-oriented default, not a recommended production upload timeout. Keep 50 MiB per file. Upload finalization invalidates task input; actual manifest/source reconciliation is outstanding.
- Add trusted review service, immutable history, evidence verification and linkage, review-specific revision checks, memory approval/retrieval ACLs, approval issuance, payload persistence and outbox dispatch. Brief replacement is a trusted server-only CAS operation, not a review permission system. Approval outbox contains binding metadata only; no dispatch. Resume from approval/input waiting intentionally blocked pending dependency checks. No auto-send.
- Run authenticated security, real concurrent database, lease/worker restart, storage and manual mode regression tests; review protected changes separately. Existing app build, full typecheck, debt, billing and takeoff regression gates remain with Gavin. No app run, credentials, network, migrations, generated types, dependencies, UI, or deployment in this delivery.

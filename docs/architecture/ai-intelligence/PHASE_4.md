# Phase 4 — Estimate reconciliation and review (isolated service layer)

Baseline e2209d3e; builds on cumulative 1A, partial 1B, 2A, 2B and Phase 3 preparation. This is an additive, default-off preparation/reconciliation layer, **not** the completed live estimating milestone. No app mount, pricing writes, quote creation, provider calls, migrations, deployments or new npm dependencies. The existing manual path remains untouched.

## Delivered

- `app/lib/intelligence/estimating/snapshot.ts`: strict bounded server snapshot contract, explicit canonical quote scope, library ownership, saved rates/pack data, verification of measurement source/basis, independently versioned geometry/pricing/library/totals, saved cost rows, tax and margin context, persistent-disposition projection. These are domain projections, not Supabase row types. No client or model may populate the snapshot.
- `reconcile.ts`: document readiness, geometry completeness, provenance and quantity reconciliation, unpriced measurements, obsolete/unapproved/missing library mappings, unit and version mismatch, duplicate line checks, missing/zero rates, pack data, saved cost mismatch, estimate scope dispositions and canonical builder total comparison. Evidence-linked findings are prioritized; exact normalized name/alias suggestions are unselected, never automatic matches. No inferred products, costs, quantities, allowances or margins.
- `service.ts`: a server-only unregistered `EstimateStore.transactEstimate` port, explicit user admission with independent price-view and estimate-review grants, fresh source/task/revision checks, review queue commands (persist only review dispositions and audit metadata), and approval binding preparation (not a receipt). The current snapshot digest binds the full reviewed brief and all snapshot inputs, actor, policy and job input hash. Changes invalidate approval preparation; disposition revisions bind geometry, pricing, library and totals. No price/measurement/geometry writes. No quote or send authorization.
- `tests/intelligence/phase4.test.ts`: 16 isolated tests, including Phase 2B review → Phase 3 candidate handoff → synthetic authoritative verified measurement and saved price snapshot → Phase 4 review and approval binding. The candidate is NOT treated as verification. The fixture stands in for missing live adapters.

## Existing engine reuse and boundaries

The live `quotes/actions.ts` recalc path uses `computeMaterialCostByStrategy`, entry values after pitch/waste, spacing and sold-by-lineal cover conversion, pack round-up, and saved labour rates. Phase 4 consumes the adapter's **final priced quantity**, never applies these geometry or purchasing conversions again. It checks saved material cost through `app/lib/pricing/engine.ts` and saved labour cost against the saved rate, not a model estimate. The unit must be the canonical priced unit (exact string); source quantity must match the confirmed brief's canonical unit/value/basis if linked. Actual pricing basis, pitch, waste, segmentation, cover and approved manual adjustments must already be verified by the current legacy engine and authorized review. The source excerpt stays in the brief; findings carry its IDs. Source geometry not independently verified here.

For totals, the existing Summary page uses `computeQuoteTotals` on stored costs, separate quote tax rows via `computeTaxLines`, and custom lines. This initial checker reuses the first two engine functions and compares to a fresh authoritative builder-summary total for **component-only** snapshots. A missing/incomplete canonical total, unsupported custom lines, or mismatch blocks readiness. It intentionally does not use the customer quote editor's saved amounts, which are a separate presentation/approval artifact. The adapter must mark unsupported configurations incomplete or unsupported; no manual rounding, currency conversions or guessed legacy tax fallback. Strict numeric comparison tolerance 1e-7 is provisional, not a currency rounding policy; test against actual canonical stored precision. Zero rates require explicit authorization flags; zero pack price is conservatively held by the existing engine. Negative/credit/discount rows and unsupported custom amounts are outside this first projection. Per-component approved rate overrides, labour-only/custom allowances, currency precision, quantity corrections and complex trade conversions need dedicated adapter validation; if effective saved rule cannot be attested, withhold readiness. Do not mislabel an override as a library rate to satisfy this check.

## Review workflow

1. Load canonical snapshot and complete brief with current rights. Show findings, source IDs, candidate library IDs and existing line IDs in the existing estimate UI (not delivered here). Missing/ambiguous scope remains visible, including access, flashing and product requirements. No fuzzy matching or AI-led scope expansion in this batch.
2. Human reviews and uses existing manual editors for changes to component, quantity, prices or allowances. Review commands only accept target kind, ID/version, outcome, line IDs and reason. Actual included scope must link to current, valid priced lines. Quantity facts must link to matching verified measurements. Excluded source quantities cannot remain priced. A commercial finding cannot be generically resolved to hide it. Phase 2B `resolved` clarification may be refined to a commercial disposition; not-applicable must remain consistent. Review actions are metadata, not changes to the original brief. All confirmed facts and nonsuperseded issues require current dispositions; every priced row must be linked. These conservative checks can block valid edge cases; manual path remains available. Review queue projection is derived on every read and not a new task scheduler. Existing issue records remain persistent under the brief adapter; current estimate dispositions and audit events need durable storage. No prior-disposition history store added here; adapter must preserve revisions/old decision content if required by approved audit retention.
3. Review command requires fresh preview digest, current record version and reviewer right; persist dispositions/audit atomically. On changes to canonical data or any of the four revisions, re-open review. Version hashes must be content/revision derived by adapter, change on any relevant edit, including approved rate, alias, geometry or tax/total changes. Review metadata is not a signature. An estimate can be ready **for review**, not approved or quote-ready. `totalCheck` is diagnostic only when blocked; `canonicalBuilderTotal` is null when blocked.
4. `prepareApproval` returns existing `ActionBinding` and its hash only if no blocker; bind exact digest and idempotency key. It creates no approval receipt/outbox or side effect. Future approval and consumption need fresh recomputation and atomic admission, version/reviewer rechecks and existing Phase 1B policy. Do not reuse this binding for `prepare_quote` or `send_quote`. No real pricing or customer draft produced.

## Integration gate for Gavin

Implement `EstimateStore` as an authorized transaction covering current quote, its company and section permissions, job/brief, source/task state, measurements, geometry/calculation revisions, current company library/approved effective saved pricing rules, canonical summary totals and review dispositions. The separate store contract is intentional: avoid trusting independently fetched snapshots between checks. Validate tenant/quote ownership for every nested row (not merely a scope wrapper), including measurement/component entries, linked library and taxes; resolve canonical quote component IDs and verify disposition links. Verify completeness and price-view permission before disclosure; use server time, no worker or demo fallback. Load only bounded data or return an explicit incomplete state; never truncate silently. Revoke reviewer authority on role change, reconcile stale dispositions; use optimistic version/locking and idempotent audit/persistence, RLS and transactional rollback. Durable transaction, RLS, current real permissions, actual quote financial snapshot, live library guard, scope mapping, UI/UX, audit history and review queue are not integrated. Adapter must not persist any other snapshot fields through this port. Integrate real reviewed measurements and Phase 3 staging first; do not derive verified quantities from Intelligence candidates. Use existing legacy editors for actual edits; no automated add/price action or live approval until owner sign-off.

Before proceeding to any live quote preparation, test real roofing jobs with multiple areas, custom lines, overrides, supported/unsupported units, pack and cover conversions, zero-rate permissions, discounts, rounding/taxes and multiple currencies, archived library IDs, manual revisions, deleted rows, stale receipts, concurrency and revocation. Validate canonical builder vs customer totals separately; complete prior phase live gates and repository `AGENTS.md` gates. No headless real-world pricing accuracy or production readiness claimed. Continue Phase 5 only in isolation against approved, canonical estimate contracts until this integration is validated.

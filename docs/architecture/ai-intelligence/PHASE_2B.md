# Phase 2B — Roofing Job Brief (isolated implementation)

## Scope and evidence

Baseline e2209d3e; cumulative 1A / partial 1B / 2A / isolated 2B. This is a **local vertical slice**, not a deployed workflow or the architecture's live pilot exit gate. No existing baseline file, migration, generated DB type, billing, model default, dependency, route, or existing design primitive is modified. No credentials, customer data, infrastructure, full application build, or live provider calls used.

### New modules

- `roofing/pack.ts`: provisional versioned generic roofing extraction guidance. Conditional categories, exact source qualifiers and units, scope and revision ambiguity, no implicit product/installation requirements or policy authority. Owner/roofing expert must curate and approve before live use; no regional building standards or pricing/product catalogue supplied. The Phase 2A worker now includes this pack and a new prompt version in its existing hashed page request. Provider outputs remain constrained to existing candidate schemas and trusted evidence IDs.
- `roofing/compile.ts`: validates trusted persisted run binding, exact analyzed page/output counts, current source revision/hash/transform, page-local evidence, scope, run ID and candidate identity. Compiles versioned proposed facts and open issues; selects relevant analyzed pages; preserves original quantities and all source evidence. Partial coverage and absent facts are explicit review items. Deterministic, conservative reconciliation: explicit named roof declarations (`Roof A: pitch = ...` or `material`, `roof system`, `underlay`, `insulation`) with differing values are potential discrepancies, not proven conflicts; alternatives/conditional values excluded; exact `See sheet R-05` / `Sheet: R-05` patterns signal unmatched references; explicit TBC/TBD/unknown/by others values flag missing or assigned scope; repeated identical stated quantity proposals flag duplication, never sum or convert. No filename-based revision precedence. Real-world prose, complex detail cross-references, units, regional and multi-building disambiguation, inconsistent dimensions, geometric quantities, OCR and visual conflict interpretation need pilot evaluation; current rules are intentionally narrow and may miss issues or flag equivalent values. No issue count or finding count is an accuracy measure.
- `roofing/review.ts`: server-only transaction service using the existing IntelligenceStore adapter. Authenticated user with fresh `canReview`, scope, entitlement, enabled policy and revision guard; explicit create from completed/waiting-for-input run without in-flight intent. Reject stale/foreign runs and active work; compare-and-swap job and record versions. Confirm/reject facts; correct full candidate fields (requires fresh confirmation); resolve/not applicable issues only; select working pages without deleting source records. Record prior review data/reason in private, bounded history; operational audit only event/target. Updates invalidate earlier job input binding. No component inclusion/exclusion or external side effects. Coverage cannot be overridden by issue closure. `roofingReviewView` produces sorted review items, page status, source references and normalized boxes, coverage, next action and blockers; service adds trusted worker failure reasons. No signed URLs or client authority. `briefMarkdown` remains the existing escaped internal renderer. Job review is not a downstream authorization.
- `app/components/intelligence/RoofingReviewPanel.tsx`: unmounted client presentation component using existing v2 QcSurface, QcNotice, QcStatusBadge, QcButton, QcField, QcInput and QcActionNotice, local pending guard and stale-version notice. Shows coverage, prioritized issues, findings, source page links, manual fallback, review reasons, wording corrections, source-page selection and blockers. Parent must wire authorized source viewer and manual path; onApply resolves only after a confirmed server mutation and refreshed snapshot. No direct service import at runtime, no fetching, no raw HTML, no route registration. The wording correction controls preserve quantity/source data; full quantity correction UI and viewer zoom must be validated/implemented in the app. TSX syntax checked only; React/Next typecheck, accessibility and real-device interaction not tested.
- `persistence/store.ts`: optional private `roofingReviewHistory` (max 2000 records in service; require approved retention/archive before live operation). Store must atomically roll back all mutations on rejection. History may contain confidential findings and prior decisions; never expose indiscriminately, never log to telemetry or global learning. No actual DB persistence.
